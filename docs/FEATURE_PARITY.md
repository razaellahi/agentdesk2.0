# Feature parity and implementation ledger

Updated 2 October 2026. **Full legacy parity is not complete.** This ledger replaces the old completion marks, which did not have sufficient evidence and used an outdated VRS baseline. A rendered screen, copied wrapper or passing mock test does not prove the full source behavior.

## Scope and source baseline

- Unified Agent: every feature, `develop` at `1a2bfe7ac89529347d0d56ae41834100d2e535da` (delta from `dfbd13e8` reviewed 13 October 2026: only voicemail/voice routing and the CRM `CONVERSATION_DATA` target changed; voice items are out of this pass).
- Unified Admin: Agent Desk Settings only, `develop` at `ee72cc3fb531576638f25caf745a9e67f3e02694`. Language selection/fallback/RTL belong to the agent platform; unrelated Admin languages/translations CRUD is excluded.
- VRS frontend: every feature, `origin/develop` at `dcaf1c6328592ab9fbca8055a0230e764d4101f7`. The earlier master/PTCL references are superseded.
- Multi-chat: an enhancement with one operational session, isolated per-channel drafts, 1–3 panes and controlled pop-outs. The linked reference was read and reconciled in [MULTI_CHAT_REFERENCE.md](MULTI_CHAT_REFERENCE.md).

[CONSOLIDATION_PLAN.md](CONSOLIDATION_PLAN.md) records the architecture, exact settings fields, phases and acceptance requirements. [SOURCE_INVENTORY.md](SOURCE_INVENTORY.md) records source surfaces and protocols. Later develop changes need a migration delta review.

- Case Management front end: everything in `case-console` (console + Agent Desk widget), `ui_f-revamp` at `2b4bba3` of `/EF/case-management` (a superset of `develop`). The case backend stays in that repo; see [Case Management](#case-management).

## Evidence rules

**Partial** means implementation exists but a named subbehavior or full acceptance scenario remains open. **Blocked** names a specific missing dependency or backend proof. Nothing below is a release-complete checkmark. Test evidence applies only to the scenario actually exercised.

Local evidence includes permission/resource and PII tests; API refresh/identity isolation; conversation/delivery/linking/outbound reducers; draft/board stores; email envelope/recipient semantics; voice call-leg/MRD models; dashboard layout/metric adapters; recording normalization/filter/CSV/WAV helpers. Browser suites exercise mock login/2FA/preferences, settings permissions/validation/dirty state, dashboard widgets, split/mobile/pop-out/email workspace, and recording columns/archival. See actual test files and the latest run report below; live SIP/Finesse/CRM/SSO/reporting/VRS acceptance is still required.
